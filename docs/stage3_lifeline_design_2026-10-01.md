# 阶段三设计方案：细胞、级别一（Monod）模型、lifeline 记录与分析

日期：2026-10-01　分支：`test`　状态：方案，待用户确认后实施

对应研究计划 `docs/lifeline_research_plan.md` 的第 4.1、5、6.3 到 6.6 节和里程碑的阶段 3，并吸收了第 13.2、13.3 节（Haringa 2023 的 lifeline 分析口径）。

## 1. 核心决定：细胞挂在流体粒子上

用户在 9 月 26 日已定：不设独立的 CELL 粒子，生物量作为流体粒子的一个不扩散的标量。SPH 的流体粒子本身是拉格朗日的，
每个粒子天然有一条轨迹，3 mm 算例的 109 万个流体粒子就是 109 万条 lifeline。

这个决定让研究计划第 6.3 到 6.5 节的大部分需求消失：

| 研究计划原需求 | 挂在流体粒子上之后 |
| --- | --- |
| 新的粒子种类 CELL，参与邻居搜索 | 不需要 |
| 细胞速度由流体插值、位置单独推进 | 不需要，细胞就是流体粒子 |
| 细胞处的浓度用 Shepard 插值 | 不需要，读本粒子的 C_s |
| 摄取量按核权重分配给邻居，原子累加 | 不需要，在本粒子上直接扣，逐粒子严格守恒，无非确定性 |
| 粒子池重排保留细胞及其对应关系 | 已有：标量随 defrag 搬运，永久编号 uid 已实现 |
| 细胞粒子数的收敛性（Haringa 警告的伪梯度） | 不存在离散化噪声；收敛性只针对"抽样多少条 lifeline 做统计" |
| 被动示踪假设的验证（阶梯第 5 级） | 自动成立；只需说明 PST 位移对轨迹统计的影响 |

需要新增的只有三样：反应项、连续加料源、lifeline 记录与分析。

**一个要提前说清的研究设计问题。** 级别一模型里摄取率只取决于当地的 C_s 和 X。若 X 处处相同，"粒子级的双向耦合"与 Haringa 的
"均匀欧拉生物量汇"在数学上是同一件事。所以级别一的对比只有"有汇"与"无汇"两档，它的作用是打通框架、完成零维极限和守恒审计。
粒子级方法真正不可替代的地方在级别二：生长率 μ 向平衡值弛豫（时间常数 τ），μ 是粒子自己的历史量，欧拉方法要用群体平衡方程才能表达，
而我们只是每个粒子多一个状态。这一点决定论文的卖点应落在级别二，阶段三只做地基。

## 2. 物理模型（级别一）

每个流体粒子携带（单位取比量，随粒子输运不变，守恒量为 Σ m_i ·值）：

| 场 | 含义 | 单位 | 扩散 | 备注 |
| --- | --- | --- | --- | --- |
| C_s | 底物浓度 | mol/kg | 分子扩散加标量 SGS | 已有的标量机制 |
| X | 生物量浓度 | g/kg | 无 | `turbulent: false, diffusivity: 0`，配置里已预留这种场 |
| U | 本粒子累计摄取的底物 | mol/kg | 无 | 新增；用于守恒审计和 lifeline 的积分量 |
| F | 本粒子累计获得的进料 | mol/kg | 无 | 新增；用于守恒审计 |

四个场正好占一个 vec4，标量部分的开销最小（9 月 26 日估计每步 3% 到 5%）。

反应（每粒子、每步，在 `predict.comp` 应用标量增量之后）：

    q_s = q_max · C_s / (K_s + C_s)                    比摄取率，mol/(g·s)
    ΔC  = C_s · [1 − 1/(1 + q_max X Δt / (K_s + C_s))]  半隐式，保证 C_s ≥ 0 且 ΔC ≤ C_s
    C_s ← C_s − ΔC,    U ← U + ΔC,    X ← X + Y_xs · ΔC（生长可关）

- 时间尺度：Haringa 的参数下 t_uptake = K_s/(q_max X) ≈ 0.3 s，时间步 6.6 × 10⁻⁵ s，显式或半隐式都稳定；半隐式多做一次除法，换来正定。
- 生长在 100 s 量级的窗口内只有约 1%，默认关（X 为常数），留开关给零维极限的批式验证。

加料（连续源，新的注入模式）：现有注入槽是"球内置为给定值"的脉冲。新增"速率"模式：球内每个流体粒子每步

    ΔC_s = ṁ Δt / M_feed,     F ← F + ΔC_s

M_feed 为球的名义质量 ρ₀ · (4/3)πR³。球内实际粒子数随时间有百分之几的起伏，所以实际进料量不等于 ṁΔt，
但 F 逐粒子记录了真实加入量，累计进料 = Σ m_i F_i，审计是精确的。

守恒审计（任意时刻，逐粒子成立，求和后只受扩散项舍入影响）：

    Σ m_i (C_s + U − F)_i = 常数（= 初始底物总量）
    Σ m_i (X − Y_xs U)_i = 常数（开生长时）

## 3. lifeline 记录

- 抽样：按永久编号 uid 取一个固定子集（例如 uid 模某个步长），数量 N_L 可配。
- 记录量：每条 lifeline 每次记录 q_s/q_max（由 C_s 算，1 个 float32）；位置和 U 以较低频率另存（用于轨迹图和校核）。
- 节奏：0.03 s（Haringa 2023 的口径），3 mm 算例为每 457 步一次。
- 实现：在 headless 运行脚本里每次读回标量缓冲和 uid（3 mm 约 27 MB，耗时十毫秒量级），按 uid 排序对齐后追加到文件。
  与探针记录共用一次读回。
- 数据量：N_L = 2 × 10⁴、100 s：2 × 10⁴ × 3333 × 4 B = 270 MB。N_L = 10⁵ 时 1.3 GB。Haringa 用 2500 条、2000 s。
- 文件格式：npz 分块（每 10 s 一个文件），含 uid、时间、q/q_max 矩阵；分析脚本按块读。

PST 位移对 lifeline 的含义：粒子的轨迹包含位移修正，9 月 27 日量过它相当于约 10⁻⁴ m²/s 的附加扩散，
这部分已包含在混合时间的验证里。粒子携带的 C_s 是它自己的量，历史自洽，不需要插值，这是与欧拉加示踪点方法相比的优点。

## 4. lifeline 分析工具（按 Haringa 2023 第 2.3.4 节）

新脚本 `experiment/v1/checks/_analyze_lifelines.py`：

1. 信号预处理：q/q_max 做 0.36 s 滑动平均。
2. 代谢区间：饥饿 S（< 0.05）、限制 L、过量 E（> 0.95），带 0.01 的滞后防止抖动。
3. 区间停留时间分布：按六种转换模式（LEL、LSL、ELE、ELS、SLE、SLS）统计每段的持续时间。
4. arc 分析：以 0.05 为阈值，记录每段的持续时间与峰值。
5. 收敛：统计量随抽样 lifeline 条数（例如 10²、10³、10⁴、全部）和随时长的变化。
6. 输出：各区间的时间占比、停留时间分布图、arc 的持续时间与峰值散点、收敛曲线。

脚本先用合成信号（已知停留时间分布的随机电报信号）自测，再用于算例。

## 6. 算例 C（阶段三的目标算例）

30 L 槽，当前标准设置（3 mm 薄板，不开重力，p_b 2000）。

| 项目 | 取值 | 依据 |
| --- | --- | --- |
| 动力学 | q_max = 1600 µmol/(g·h)，K_s = 7.8 µmol/kg | Haringa 2023，便于直接对照其区间统计 |
| 生物量 | X = 55 g/kg，均匀，不生长 | 同上 |
| 进料 | 顶部液面下一点，连续，ṁ = 2.0 × 10⁻⁴ mol/s | 使槽平均 q/q_max ≈ 0.28，与 Haringa 的 54 m³ 工况相同 |
| Da_mix | 约 1.5（30 L）；工业槽约 7 | 研究计划 13.2；是否提高 X 以匹配工业 Da 待定 |
| 流程 | 0 到 25 s 建立流场（不加料，C_s 取预期平均值）；25 s 起加料并记录 | 与混合时间算例同一起点 |
| 时长 | 第一轮 25 + 100 s（190 万步，约 10 小时一张 5090） | Haringa 用 2000 s；先看 100 s 的统计收敛到什么程度 |
| 变体 | C0 无汇（纯示踪，对照）；C1 有汇 | 级别一的"单向与双向" |
| lifeline | N_L = 2 × 10⁴，0.03 s | 第 3 节 |

读数：底物场的切片与概率分布、三个代谢区间的体积占比和时间占比、六种转换的停留时间分布、arc 统计、随 lifeline 条数和时长的收敛。

## 9. 需要用户定的

1. **动力学参数用哪一套**：Haringa 的青霉菌 Monod 参数（可直接对照其区间和 arc 统计，本方案的默认），还是酿酒酵母（为级别二的溢流代谢铺路）。可以先用前者做验证，级别二再换。
2. **是否在 30 L 槽里匹配工业 Da**：把 X 提高约 5 倍使 Da_mix 从 1.5 到 7，梯度更明显；代价是偏离 Haringa 的原参数。
3. **lifeline 条数和记录量**：2 × 10⁴ 条、0.03 s、只存 q/q_max（270 MB / 100 s）是否合适。
4. **进料位置**：用数据集里示踪剂的注入点，还是另定。
5. **级别一里生长是否打开**：建议关（100 s 内只变 1%），只在零维批式验证里开。
