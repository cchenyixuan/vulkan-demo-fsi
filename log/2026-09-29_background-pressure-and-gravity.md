# 2026-09-29 背景压力 p_b 选项；开重力的算例流体穿过槽壁

## 背景

Rushton 桨的力矩（除以质量系数后）比 Fluent 低 37%，Rushton 区的径向排出流也偏弱
（r = 52 mm 处径向速度峰值 0.46 U_tip，向外流量 0.58 N·D³）。75 s 的算例里 20 s 之后力矩没有漂移，
所以不是没跑够。已排除粘度、ξ、叶片厚度、叶尖半径、渗漏、槽壁摩擦和力矩读数方法。

当前怀疑：叶片背面的负压传不到叶片上。

- Fluent 里 Rushton 力矩 99.5% 来自压力，折合叶片两侧压差约 600 Pa，其中大部分来自背面的低压。
- 我们关了重力，也没有背景压力，槽内平均压力在 0 附近，背面是负压。
- `force.comp` 在自身压力为负时把 (P_i + P_j) 换成 (P_j − P_i)（TIC）。这个形式不是成对反作用的力。

用户要求提交两个算例做对照：一个加背景压力 p_b，一个开重力，其余保持当前设置
（3 mm，单层贴体叶片，无外皮，ξ = 0.01，ν = 1.0e-6 m²/s，c₀ = 20 U_tip）。

## 合作者原来的代码

`density.comp`：

```
P = B [ (ρ/ρ₀)^γ − 1 ],   B = ρ₀ c₀² / γ
```

流体和固体都用这一式。固体每步把密度重置为 ρ₀，压力只由本步的增量决定。

## 我们改成了什么

### 1. 背景压力 p_b（默认 0，不改变现有算例）

```
P = B [ (ρ/ρ₀)^γ − 1 ] + p_b
```

| 位置 | 改动 |
| --- | --- |
| `common.glsl` | 新增 spec 常量 `BACKGROUND_PRESSURE`，id = 34，默认 0 |
| `density.comp` | `new_pressure = eos_constant * (pow(...) - 1.0) + BACKGROUND_PRESSURE` |
| `utils/sph/case.py` | `PhysicsConfig.background_pressure: float = 0.0`；`_SPEC_CONSTANT_MAPPING` 加 id 34 |
| `simulator_v1.py` | `SPEC_ID_BACKGROUND_PRESSURE = 34`；`_global_spec_entries()` 加一项 |
| 搅拌槽生成器 | `--background-pressure`，非零时才写入 case.yaml |
| `CLAUDE.md`、`shaders/README.md` | 空闲 id 范围改为 35–39 |

流体和固体都加 p_b。固体也加的原因：固体压力 P_s 进入流体与固体的压力对 (P_f + P_s)，
两边都抬高 p_b，壁面对流体的作用才与流体之间的作用一致。

只能用于封闭、没有自由液面的算例。

### 2. 静水压初始密度（默认关闭）

`PhysicsConfig.hydrostatic_reference`：静水压为零的参考点（封闭槽取顶盖高度）。给定后流体粒子的初始密度为

```
p(x) = ρ₀ g · (x − x_ref),   ρ = ρ₀ (1 + p / B)^(1/γ)
```

在 `simulator_v1.py` 上传 `density_pressure` 时计算，只对流体。生成器选项 `--hydrostatic`（需要同时给 `--gravity`）。

### 3. 运行状态日志

`_check_blade_leak_tracking.py run` 新增 `--status-log`：每 1000 步记录一行，

- 活粒子数，overflow_inside、overflow_incoming、correction_fallback；
- 全槽流体压力的均值、1% / 50% / 99% 分位数、负压粒子的比例；
- Rushton 区（r < 72 mm，y = 18.7–58.5 mm，与 Fluent 的 rt_rotorbox 相同）的同样五个量；
- 流体密度的均值、最小值、最大值。

`--dump` 的文件里增加 `density_pressure`。`simulator_v1.py` 新增 `readback_density_pressure()`。

### 开重力：流体穿过槽壁

| 算例 | 步数 | 活粒子数（初始 1,360,100） | 越过槽内表面的流体粒子 | 其中深于 3 mm |
| --- | --- | --- | --- | --- |
| 重力，当前设置 | 4000 | 1,278,169 | 113,700 | 103,113 |
| 重力 + p_b = 3500 Pa | 10000 | 1,358,766 | 12,593 | 8,947 |
| 重力 + 静水压初始密度 | 6000 | 1,151,125 | 139,938 | 128,471 |
| 重力 + 静水压初始密度 + p_b = 1000 Pa | 6000 | 1,340,178 | — | — |
| 重力 + 静水压初始密度，旧的默认几何（三层叶片加外皮） | 2000 | 1,358,795 | — | — |

- 穿出的位置：槽底最多（66,952 个），其次是侧壁（36,161 个），顶盖没有（"重力，当前设置"算例，深于 3 mm 的粒子）。
  穿出槽壁的粒子继续下落，离开网格后被删除，所以活粒子数减少。
- 静水压初始密度确实生效，但维持不住。"重力 + 静水压初始密度"算例：

  | 时刻 | 高度 70 mm 处压力中位数，Pa | 流体平均竖向速度，m/s | 槽底壁面粒子压力中位数，Pa |
  | --- | --- | --- | --- |
  | 20 步（0.0013 s） | 3059（静水压应为约 3500） | −0.008 | 0 |
  | 300 步（0.0197 s） | 316 | −0.152 | 0 |

  0.02 s 内静水压就消失了，流体以接近自由落体的速度下落（g·t = 0.19 m/s）。槽底壁面粒子的压力中位数是 0。
- 旧的默认几何同样丢粒子，所以与叶片做法无关。

**判断**：槽壁托不住静水压。固体压力只由一步的密度增量决定（P_s = EOS(ρ₀ + dt·(Dρ/dt)_s)），
流体静止时增量为零，P_s 也就为零；槽底的流体有几千帕压力，壁面粒子没有对应的压力。
这一条是从现象推出来的，没有逐项验证；9 月 25 日 4 mm 平底槽开重力的算例能跑到 23.5 s，
两者的差别（碟形底、3 mm、之后的代码改动）没有分辨。

p_b 不受这个问题影响：固体粒子的压力也加了 p_b，壁面和流体一致。

### 解读

- 前提成立：基准算例里 Rushton 区有三到五成流体处于负压。
- p_b 的主要效果是全槽整体旋转减弱。推测原因：挡板的阻力也来自压差，背面同样是负压；
  p_b 让挡板的阻力恢复，整体旋转减弱，叶片与流体的相对速度增大，两个桨的力矩都上升。
  这个解释与"基准算例的力矩随时间下降、PBT 力矩也上升"相符，但挡板受力没有直接测量，属于推测。
- 总力矩和平均速度向参考值靠拢：总力矩与 Fluent 差 −12%（基准 −29%），与 M-Star 差 −3% 到 −8%；
  全槽平均速度与 Fluent 差 −2%（基准 +14%）。
- 两桨的分配仍然对不上：Rushton −25%，PBT +35%（相对 Fluent）。整体旋转现在比 Fluent 弱 18%。
- Fluent 的参考值是 t = 25 s 的单个时刻，我们的各区速度是 t = 30 s 的单个时刻。

### 没有回答的问题

1. 结果是否依赖 p_b 的取值。p_b = 1000 Pa 时 Rushton 区仍有 0.2%–0.5% 的粒子是负压。需要 p_b = 500 和 2000 Pa 的对照。
2. 挡板受力是否如推测的那样增加。需要读回壁面粒子受的力，现在 `force.comp` 对 BOUNDARY 粒子直接返回，不计算。
3. p_b 算例 30 s 时是否已经稳定。需要跑更长时间。

## 有什么影响

- p_b 默认为 0，生成器在 p_b = 0 时不写这个键，现有 case.yaml 和结果不变。
- 静水压初始密度默认关闭。
- `--status-log` 是新增选项，不给就不记录。
